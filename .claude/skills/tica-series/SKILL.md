# 〜tica シリーズ

Pictica（写真を2L判などに並べて印刷用画像を作るツール）を1作目とする、同じ見た目・同じ作りのウェブアプリのシリーズ。
新しいアプリは、このキットのひな形（リポジトリ直下の `index.html` ほか）から作り、このルールに合わせる。

- 1作目の実装（迷ったらこれに合わせる）: https://github.com/saikinoBOT72/collage-generator の `index.html`
- 参考画像: `reference/pictica-icon.png`（アプリアイコン）、`reference/pictica-logo.png`（タイトル画面とヘッダーのロゴ）

## 1. 名前

- 「〇〇tica」と書いて「〇〇チカ」と読む造語にする（例: Pictica = picture + tica → ピクチカ）。
- 表示は英字の名前だけ（例: `Pictica`）。読みはタイトル画面や説明文で補う。
- 決める前に必ずウェブ検索で次を確認し、候補を3〜5個、それぞれ確認結果を添えて提案する。おすすめを1つ選ぶ。
  - 同じ名前のアプリや商品がないか、まぎらわしい既存ブランドがないか
  - 他の言語で変な意味にならないか。特にスペイン語・イタリア語・英語のスラング
  - 過去に避けた例: Hanatica（イタリア語 natica = お尻を含む）、Futatica（futa が英語圏の成人向けスラング）、Tetica（スペイン語の卑語）、Cotica（イタリア語で豚の皮）、Tomotica（トミカと紛らわしい）
- 「tica」自体はスペイン語で「コスタリカの女性」の愛称で、悪い意味はない。
- 名前は作者が決める。決まるまでは仮の名前で進めてよいが、そう伝える。

## 2. 見た目

### 色（ひな形の `:root` にあるトークンをそのまま使う。値は変えない）

| 役割 | 値 |
|---|---|
| シリーズの4色 | ピンク `#F2A7B5` / 黄 `#F7D27A` / 緑 `#A8D5A2` / 水色 `#9CC7E8` |
| メインのボタン・スイッチ・選択中の塗り | ピンク（白文字をのせてよい） |
| 文字・アイコン・選択の枠に使う濃いピンク | `#DB7A92` |
| 背景 | 白 `#ffffff`。作業エリアだけ薄いグレー `#F2F2F4` |
| 文字 | `#3E383B`、補足は `#8C868A` |

- **白が基調。ベージュやクリームの背景にはしない。**
- 4色は「区別」に使う。設定のセクションごとに黄・緑・水色を割り当て、見出しのアイコンを色付きの角丸にのせ、下のタブで選ばれているアイコンの背景をその色にする。ピンクはメインの操作用に取っておく。
- 白文字はこの4色の上ならどれでも使ってよい（シリーズの決まり）。
- ダークモードも用意する（ひな形の `@media (prefers-color-scheme: dark)` と `:root[data-theme="dark"]` の両方）。
- フォントはシステムフォント（`--font`）。外部フォントは読み込まない。

### 画面の構成

- **タイトル画面**: ロゴ（大きく、影なし、角を切らない）→ 名前（40px・太字）→ 4色の丸 → 一言の説明 →（新しい版があればアップデートの案内）→ ボタン2つ →「🔒 データは端末の外に送信されません ・ プライバシーポリシー」→ バージョン表示。
  - ボタンは上から「**最初から**」「**前回の続きから**」。保存された内容があれば「前回の続きから」をピンク（メイン）にし、下に「前回: 〈概要〉（日時）」を出す。なければ「前回の続きから」は押せない状態にして「保存されている内容はありません」と出す。
  - 消える作業があるときに「最初から」を押したら、その場で警告を出す（「前回の内容（〈概要〉）は消えます。最初からはじめてもよいですか？」＋「やめる」「消して最初から」。消すボタンは赤）。
  - ヘッダーのロゴを押すとタイトル画面に戻る。このとき「前回の続きから」は今の作業に戻るボタンになり、「最初から」の警告は「今の内容は消えます」になる。
- **ヘッダー**: 左にロゴ（30px）と名前、右に「戻る」「やり直す」（記号だけのボタン）と、ピンクのメインボタン（例: 書き出す）。右側のボタンは必ず右端に寄せる（`.header .spacer { flex: 1 }`）。
  - 「端末内で処理」などの表示はヘッダーに置かない。プライバシーの案内はタイトル画面と設定パネルのリンクだけ。
  - スマホでも名前が「P…」のように切れないようにする（`flex: none`。340px 未満でだけ隠す）。
- **作業エリア**: 薄いグレーの上に、白い紙やカードをのせる。作業エリアからはみ出さない大きさに収める。
- **設定**: PC とタブレット横向きは右に 340px のパネル（全セクションを縦に並べる）。スマホとタブレット縦向きは下のタブ＋ボトムシート（開いている間は作業エリアをなるべく広く。見出しに「完了」ボタン）。
- **スマホ横向き**（高さ 520px 以下）: 左に作業エリア、右の列に操作をまとめる。
- 空き枠などの点線は SVG で描く（CSS の dashed は、スマホで左右が欠けることがある）。
- `confirm()` / `alert()` は使わない（埋め込み表示では出ない）。消す操作は「戻る」で戻せるようにするか、画面内で確認する（タイトル画面の警告や、ひな形の `armButton` の「もう一度押すと削除」方式）。
- お知らせはトースト（画面上部の中央、黒地に白文字）。作業中の部品（ページ一覧など）にかぶらない位置に出す。

### アイコン

- アプリアイコンとロゴは、`reference/pictica-icon.png` と同じテイストにする。
  - 2×2 の角丸のマス（シリーズの4色）
  - 作者のキャラクター（花の女の子と葉っぱの男の子）が、白いふちのステッカーのようにマスからはみ出す
  - 線は白
- **アプリアイコン**（`icon-180/192/512.png`）: 背景あり（不透明）で、少し拡大して余白を減らす。角丸は OS がかけるので画像では付けない。
- **ロゴ**（`logo.png`）: 外周の余白なし・マスの間は透明。CSS で角丸や影をつけない（絵の端が切れるため）。
- 新しいアイコンを作るときは、作者に元のイラストを用意してもらう。キャラクターを勝手に描き起こさない。それまではひな形の仮アイコン（4色のマス）のままにする。

### 言葉づかい

- 日本語。ユーザーから見た言葉で、短く、具体的に（例:「写真を選んではじめる」「自動で並べる」「書き出す」）。
- エラーは、何が起きたかと、どうすればよいかを書く。謝罪の決まり文句は入れない。

## 3. 作り

- **HTML ファイル1つ**で動く（CSS と JS はインライン）。ダブルクリックで開いても、GitHub Pages に置いても使える。
- **ほかのサイトと通信しない**。CSP は ひな形のまま（`connect-src 'self'`。同じ場所の `version.json` を読むためだけ）。外部の CDN・フォント・アクセス解析は使わない。ユーザーのデータ（写真など）は端末の外に送らない。
- **戻る / やり直す**: 中身が変わったら `changed()` を呼び、操作がひと区切りついたところで1回記録する。指で操作している途中は記録しない。画面の切り替え（ページやタブの移動）は「戻る」の対象にしない。キーボードは Ctrl / ⌘ + Z と Ctrl / ⌘ + Shift + Z（または Ctrl + Y）。
- **前回の続きから（自動保存）**: 作業の中身（`state.doc`）は、この端末のブラウザ内（IndexedDB）に自動で保存する。
  - 写真などのファイルは `doc` に入れず、`fileStore` に保存する。続きから再開するときに読み戻す。
  - 保存は「最初から」か「前回の続きから」を選んでから始める（開いただけで前回の内容を上書きしない）。
  - 画面を閉じる・切り替えるときにもすぐ保存する。
  - 保存できない環境や容量不足でも、アプリは普通に動くようにする（ベストエフォート）。
  - 「戻る」の履歴は保存しない。
- **設定の保存**: 次回も使う設定だけを `localStorage` に保存し、読み書きは必ず try/catch で囲む。
- **アップデート**: `APP_VERSION`（index.html）と `version.json` の `version` は常に同じ番号にする。
  - 公開するたびに上げる。機能追加は 1.1.0 → 1.2.0、修正だけなら 1.1.0 → 1.1.1。
  - `notes` に変更内容をひとことで書く。
  - 古い版を開いている人のタイトル画面に「アップデート」が出る。押すと作業を保存してから最新版を読み込み直す。
- **タッチ操作**: ピンチ・回転などは Pointer Events で書き、作業エリアには `touch-action: none`。iOS のページ拡大は `gesturestart` で止める。回転は 0 / 90 / 180 / 270° の前後で「引っかかる」（離したときに勝手に吸着させない）。
- 画像を書き出すアプリは、印刷サイズに合わせた dpi を JPEG/PNG に書き込む。複数枚なら ZIP でまとめて保存できるようにする（Pictica の `withDpi` と `makeZip` を参考に）。
- 複数の作品（ページなど）を扱うときは、それぞれが自分の設定を持つ。サムネイルや書き出しで、開いているものの設定を使ってしまわないよう、描画・計算の関数は対象の設定を引数で受け取る。
- **プライバシーポリシー**: ひな形の `privacy.html` をもとに、そのアプリが扱うデータに合わせて書き換える（ファイル冒頭のコメントに、書き換える場所を書いてある）。
- アプリアイコン: `manifest.webmanifest`、`apple-touch-icon`、favicon を用意する（ひな形に入っている）。

## 4. 公開する前の確認

1. 画面の幅を変えて確認する: スマホ縦（360・390・430px）、スマホ横、iPad 縦・横、PC。横スクロールが出ないこと、名前が切れないこと、ボタンの文字が折り返さないこと、ヘッダーの右のボタンが右端にあること。
2. ライトとダークの両方で確認する。
3. 操作しても、自分のファイル（`version.json` など）以外へのリクエストが1件も出ないことを確認する（Playwright の `page.on('request')` など）。
4. 戻る / やり直すで、主な操作がすべて元に戻ること。
5. 一度閉じて開き直し、「前回の続きから」で同じ状態に戻ること。「最初から」で警告が出て、消したあとは保存がなくなること。
6. `APP_VERSION` と `version.json` が同じ番号になっていること。
7. claude.ai の Artifact として公開するときは、`<!doctype>`・`<html>`・`<head>`・`<body>` のタグと CSP の meta を外したコピーを作って公開する（ビューアが自前の枠に入れるため）。`privacy.html` と `version.json` も一緒に公開する。保存は `downloads` capability を使う（`<a download>` は Artifact の中では動かない）。共有メニューは Artifact の中では使えないので隠す。
